# ⛔️ 严格的代码风格约束 (Code Style)
1. **绝对不要使用分号 (No Semicolons)**：在 JS/TS 代码中，语句末尾一律不加分号。只在极其罕见且必要的行首（如以 `[` 或 `(` 开头时）才使用分号以避免 ASI（自动分号插入）陷阱。
2. **引号风格**：JS/TS 中统一使用单引号（`'`），HTML/JSX 属性使用双引号（`"`）。
3. **缩进**：使用 2 个空格进行缩进。
4. **命名规范**：
   - 变量和函数：`camelCase`
   - 组件名、类名、接口名：`PascalCase`
   - 常量：`UPPER_SNAKE_CASE`

# 🏗️ 架构与逻辑规范
1. **尽早返回 (Early Return)**：避免深层嵌套的 `if-else`，优先处理错误/边缘情况并尽早 `return`。
2. **函数式编程优先**：多使用 `map`, `filter`, `reduce`，避免使用 `for` 循环和状态突变（Mutation）。
3. **解构与默认值**：优先使用对象解构，并在解构时提供合理的默认值。
4. **可选链与空值合并**：强制使用 `?.` 和 `??` 来简化对深层对象属性和假值的判断。

# 💡 AI 输出行为约束
1. **不要解释过度**：直接给出代码，除非代码逻辑极其复杂或我主动提问，否则不需要长篇大论的解释。
2. **只输出有变动的代码**：在修改现有代码时，不要重写整个文件，只需提供修改的函数或代码块，并用注释 `// ... existing code ...` 标明上下文。
3. **保持纯净**：不要在代码中留下类似 `console.log('测试')` 的调试代码，除非我明确要求。
